# CodeYam Editor in GitHub Codespaces (staging)

[![Open in GitHub Codespaces](https://github.com/codespaces/badge.svg)](https://codespaces.new/codeyam-ai/codespaces-starter-staging?quickstart=1)

**This is the staging starter.** It installs the editor's `staging` npm
dist-tag, which carries changes that have not been released yet, so you can
try them in a real codespace before they ship. For the released editor, use
[`codeyam-ai/codespaces-starter`](https://github.com/codeyam-ai/codespaces-starter).
Apart from that channel, the two templates are identical.

Click the button to try the [CodeYam Editor](https://codeyam.com) with nothing
installed on your own machine. It runs in a GitHub codespace, a Linux machine
GitHub hosts for you and opens in your browser.

## What happens when you click it

1. **GitHub may show a field for an Anthropic API key.** It is optional. Leave
   it blank and sign in from inside the editor instead.
2. **The codespace opens on a welcome page.** It shows where the editor is: the
   **Ports** panel at the bottom of the window, port 14199, labelled "CodeYam
   Editor". It also says what to do if the editor doesn't appear.
3. **The codespace installs everything.** That means the editor, the Claude
   Code CLI, and a browser for screenshots. The first time takes a few minutes.
4. **The editor opens in a new tab on the New Project screen.** Pick the AI
   that should build, sign in to it, then describe what you want to build. The
   editor builds it with you against a live preview.

This repository is intentionally almost empty: no app, no `.codeyam/`. Your
project is created inside the codespace the first time the editor starts.

## Keeping your work

A codespace made from this template is not connected to a repository of your
own yet. To keep what you build, open the codespace's **Source Control** panel
and choose **Publish to GitHub**. That creates a repository under your account.
This template is never changed.

## Good to know

- **Who can see the editor:** only you. GitHub keeps the editor's port private
  and asks you to sign in to GitHub before it lets anyone through. If you make
  the port public, the editor starts requiring its own one-time token.
- **Stopping and restarting:** your files are kept, and the editor comes back
  on the same address when the codespace restarts.
- **Skipped the key, or want to add it later:** open GitHub's
  **Settings → Codespaces → Secrets**, add `ANTHROPIC_API_KEY`, give this
  codespace's repository access to it, and rebuild the codespace.
- **Using Codex or Gemini instead of Claude:** add `OPENAI_API_KEY` or
  `GEMINI_API_KEY` the same way, then pick that agent in the editor.

## How this template is made

Both files in `.devcontainer/` (`devcontainer.json` and the welcome page
`codeyam-welcome.md`) are generated by
`codeyam-editor editor devcontainer-setup --channel staging` run in an empty
directory. They are not written by hand, so they match what existing projects
get. The editor repository runs a drift check against them
(`CODESPACES_STARTER_CHANNEL=staging scripts/check-codespaces-starter-drift.sh`).
To regenerate them, run that command in an empty folder and copy its
`.devcontainer/` here.
When you change this README, make the same change in
[`codeyam-ai/codespaces-starter`](https://github.com/codeyam-ai/codespaces-starter)
unless it is about the channel.
